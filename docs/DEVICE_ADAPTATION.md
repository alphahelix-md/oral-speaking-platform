# 终端适配与验收

## 本轮范围

2026-09-24 按用户要求，先完善电脑、平板和 iPhone 尺寸布局，再安排终端真机验收。已有 Android 手机可靠性验收继续保留；麦克风拒绝/手工文字测试已由用户要求跳过。

- 手机：保留单栏口语流程；支持 320px 起的小屏与横屏，补齐左右安全边距。按钮至少 44×44 CSS 像素，输入控件 16px；保留缩放能力和键盘焦点提示。原生音频播放器限制在容器内。
- 平板：640px 起语言、模式、录音和草稿列表分两栏，进度统计合理分列。
- 桌面：1024px 起采用最多 1120px 的内容框和顶部导航；练习页题目与录音操作分栏。设置和个人页保持可读宽度。
- 手机键盘：VisualViewport 变化时更新弹窗可见高度和位置；设置内容可滚动，关闭/确认按钮保留。没有该 API 时使用 CSS 视口回退；捏合缩放不重排弹窗。
- 录音：保留现有按浏览器能力选择格式的实现。新增 MP4-only 模拟检查，验证 WebM 不可用时 MP4 原音输出和资源释放；未更换 Android 已验收的录音流程。
- 字体使用终端系统字体；覆盖简体、繁体、英文、日语和浅/深色主题。没有新增依赖、服务或凭据。

## 已执行的开发验证

- 自动检查：27 文件，216 项通过；TypeScript 与生产构建通过。
- 首轮 UI 脚本把回顾页“返回”误当作回首页，停在练习页；修正为页面现有“再次练习”入口。该脚本问题不记为产品故障。
- 本地 Chromium 布局矩阵：320×568、375×667、390×844、430×932、768×1024、844×390、1024×768、1440×1000；补充多语言与主题，共 12 组，每组 14 个页面/状态。
- 检查首页、草稿列表、模式、设置练习、答题、录音中、录音播放器、回顾、进度、个人、设置弹窗、模拟键盘、账号弹窗和录音库。核对横向越界、触控尺寸、输入字号、桌面双栏及弹窗是否超出可见视口。
- 全程使用隔离浏览器上下文、合成音频和模拟 API；外部请求拦截。不会使用用户麦克风、历史数据、训练上传或真实模型。此矩阵不是 50 次真实练习留存率样本。
- 最终矩阵 12 组 / 168 个页面状态通过，横向越界、44×44 触控、16px 输入、双栏与弹窗可见范围检查均无失败。最终结果不是实际 iPhone 的录音证明。
- 本地证据在 `.codex/qa/device-adaptation/`，包含基线与最终报告/截图。最终判定以 `final/report.json` 为准。

复核方式：启动仅本机可访问的生产预览，运行 `node scripts/qa/device-layout.mjs`。可通过 `ORAL_TEST_ORIGIN` 指定本机地址、`ORAL_TEST_BROWSER` 指定已有 Chromium 浏览器、`ORAL_PLAYWRIGHT_MODULES` 指定已有 Playwright 所在的 node_modules；脚本不会安装依赖。输出目录可用 `ORAL_LAYOUT_OUTPUT` 指定。

## 部署及真机边界

适配源码 bf7feac 已由用户报告部署完成，线上公开脚本和应用 CSS 已核验。用户已确认界面；未逐项说明 iPhone 旋转/键盘测试，不把笼统确认扩大为全部真机通过。电脑转写问题按用户要求进入 [候补清单 QA-001](QA_BACKLOG.md#qa-001电脑英语录音无法转写)，本阶段跳过。用户没有 iPhone，Safari 真机验收也按要求列为 [QA-002](QA_BACKLOG.md#qa-002iphone-safari-真机验收无设备)，未通过；现有 vivo / Chrome 暂停及继续录音、文字与刷新回放已获用户确认完整。断网真实录音完成后刷新重开亦获用户报告完整；关闭网页标签后的未提交录音草稿恢复及一次提交也获用户报告通过；已有录音下载与独立播放也获用户报告通过；下一项为录音期间锁屏后的原音与操作恢复。

Chromium 的手机尺寸与触摸模拟不等于 Safari/iPhone。Windows 环境没有已安装 WebKit 测试内核；没有声称已通过 iPhone 麦克风、Safari 编解码、真实键盘、刘海/PWA 安全区或后台恢复验收。iPhone 真机仍需验证：竖屏/横屏、弹窗与键盘、录音暂停结束、转写、原音保存和回放。桌面麦克风和其他设备的真实闭环也单列。

本轮未实现跨设备同步；每个浏览器独立保存记录。平台全量发布所需的真实 Redis/费用上限、完整故障矩阵、50 次跨设备尝试及 3 天稳定观察仍未达标。

## 实现参考

- [WebKit：Safari 18.4](https://webkit.org/blog/16574/webkit-features-in-safari-18-4/)：增加 WebM/Opus 支持。格式不能只按“是否 iPhone”固定判断，仍使用运行时能力检测。
