# 浏览器存储失败检查

2026-09-24，针对 bf7feac 前端生产构建，使用已有 Playwright/Chrome 执行四项浏览器故障注入。合成音频、独立浏览器上下文、本机服务，所有 API 模拟、外部请求拦截；真实 Provider 请求为 0。不使用用户浏览器资料、麦克风或真实存储配额。

| 场景 | 核验结果 |
| --- | --- |
| 原音写入抛出配额错误 | 明示保存失败、不请求 STT、不新增答案；实际下载字节与捕获的原音 SHA256 完全相同；草稿备份明确不含音频、未确认平台保留 |
| 原音写入事务被中止 | 未残留成功原音记录；上述提示、导出与费用保护相同 |
| 答案提交时 localStorage 配额错误 | 已有文字/原音保留、0 条答案被错误提交；导出包含待提交文字；恢复后重试保存与连续两次点击只生成1个稳定题次 |
| 收到转写后 localStorage 配额错误 | 界面仍保留收到的文字并可导出；持久状态仍为未确认，提示失败；恢复后重试保存、提交，原音完整且无第二次 STT |

全部四项均核对恢复后的原音字节哈希、保存元数据和刷新后稳定答案；没有未处理页面异常。最后一项为单片音频，后续分片不得请求的边界仍来自现有处理器测试，不扩大浏览器覆盖。

- 所测本地构建的7个前端脚本哈希与此前线上 bf7feac 核验记录一致。新测试脚本通过 `node --check`。

## 复跑

使用已有生产构建启动仅本机服务（默认 `http://127.0.0.1:3421`），运行 `node scripts/qa/storage-faults.mjs`。环境变量：

- `ORAL_TEST_ORIGIN`：仅允许 localhost/127.0.0.1 加端口；禁止生产站点。
- `ORAL_PLAYWRIGHT_MODULES`：已有 Playwright 的 node_modules 目录，不安装依赖。
- `ORAL_TEST_BROWSER`：已有 Chromium 可执行文件。
- `ORAL_STORAGE_OUTPUT`：可选证据目录。
- `ORAL_STORAGE_CASE`：可选单项 `raw-put-quota`、`raw-transaction-abort`、`submit-quota` 或 `response-quota`；不设置则执行全部。

本轮结束已关闭测试浏览器和本机服务。仅增加 QA 脚本与文档，不改变业务代码，不需要重新部署。

## 证据边界

这四项验证真实浏览器运行中的注入故障与补救链路，不代表手机真实存储满、磁盘故障、Safari、服务端预算或50次真实练习留存率已达标。旧 `scripts/test-reliability-browser.mjs` 的更广场景没有因此全部通过。
